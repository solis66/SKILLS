# 星火私聊模块改造与简历包装方案

> 目标：把 `java/chat` 里的「AI 助手（星火）」从「能跑的 Demo」改造成**简历能写、面试能扛追问**的 LLM 应用工程化实践。
> 前提事实：星火**已经接进来了**（`BigModelHandler` 是标准星火 WebSocket + HMAC-SHA256 鉴权），所以这不是「从 0 接入」，而是**改造与治理**——这恰恰是简历上更值钱的位置。

---

## 0. 一句话结论

**你已经把答案写好了，只是没落到代码里。**

`deliverables/面试题-AIGC创作链路.md` 的 **Q61** 给了重构排序（安全底线 → 状态外置 → 资源治理 → 质量 → 可观测），**Q67** 给了下一步（上下文迁 Redis / 生图·PPT 异步化 / TTFT 与 token 可观测）。

把这份清单**真正实现**，收益是双份的：
1. 简历那条从「功能罗列」升级为「问题治理 + 量化结果」；
2. 面经里 20+ 道「自曝缺陷」的题，全部改写为「我发现并修复」——**负资产直接变正资产**。

## 1. 现状诊断：为什么现在这版写不进简历

### 1.1 简历口径断层（最致命）

同一个简历里两条项目的写法差了一个档次：

| | AI 作文批改（好） | LABiliBili AIGC（弱） |
|---|---|---|
| 写法 | 根因 + 修法 + 数字 | 功能罗列 |
| 例子 | 「定位 AIMessageChunk 增量被误按累积全文裁剪的根因…修复随机缺字」 | 「打通讯飞星火 WebSocket API，经事件监听 + 异步回调…」 |
| 数字 | 90%+ / <60s / Top-K=4,6 / 阈值 0.20 / 6 条 2000 字符 | **0 个** |

现在简历第 5 条原文：

> 5. AIGC 创作链路：打通讯飞星火 WebSocket API（HMAC-SHA256 鉴权），经事件监听 + 异步回调将大模型流式响应实时回推前端，支持文生文与文生图；自研按主题生成整套 PPT 文案能力，多轮会话按 12000 字符阈值滚动裁剪。

问题：
- 4 个分句全是「实现了什么」，**没有一个「解决了什么」**；
- 最后半句「按 12000 字符阈值滚动裁剪」是**已知有 bug 的实现**——面经 Q22 你自己写了「连删 0~4 实际删掉的是原索引 0、2、4、6、8」。**简历上写了、面经上认错，面试官顺手一问就穿**。

### 1.2 面经与简历口径不一致

面经 60+ 题里，至少 20 题在说「当前实现是弱的 / 这是必须改的致命写法 / 我要主动承认」。而简历说「实现了」。

面试官的心理路径是：看简历 → 觉得「就是调了个 API」→ 问细节 → 你答「这里其实有缺陷」→ **结论从"做成了"变成"做得不怎么样"**。

改造之后同一段对话变成：看简历（写了治理动作 + 数字）→ 问细节 → 你答「原实现是抄 demo 带来的地雷，我定位到根因并这样修的」→ **结论是"能独立发现并治理生产级缺陷"**。

### 1.3 技术栈声明与项目证据不匹配

简历「技术栈」栏写了：

> 大模型与 Agent：熟悉通义千问调用、Prompt 工程、**Function Calling、LangChain、工具注册与调用**、多轮对话上下文管理。

但 LABiliBili 里**没有任何 Function Calling / 工具调用的落地**（RAG 在作文批改项目里有 ChromaDB 佐证）。面试官一旦问「你这个 function calling 在哪做的」，只能答作文批改项目——而那个项目简历里没提工具调用。**要么补落地，要么改技术栈栏**。

## 2. 改造路线（分档，按性价比排序）

### 第 0 档：前置条件（不做则全盘落空）

| 项 | 说明 |
|---|---|
| **拿到真实星火密钥** | 现状 `Constant.java` 里 `appId/apiKey/apiSecret = "xxx"`（原作者脱敏占位）。需在讯飞开放平台建应用，开通「星火认知大模型 v3.5」。⚠️ AIPPT（PPT）与 TTI（文生图）是**另外的服务**，需单独开通、单独计费 |
| **密钥绝不入库** | 用 `SPARK_APP_ID/SPARK_API_KEY/SPARK_API_SECRET` 环境变量 + `docker/config/chat/application.yml` 覆盖（项目已有 `optional:file:./config/` 外置配置约定）。面经 Q11 已把这点承认了，改造后要能说「已落地」 |
| **成本预警** | v3.5 有免费 token 额度；AIPPT/文生图按次计费。**建议本轮只改造对话链路**，PPT/文生图留到有余量时做 |

---

### 第 1 档：拆地雷（半天～1 天，性价比最高，先做这个）

| # | 改什么 | 落点 | 为什么值得写进简历 |
|---|---|---|---|
| **A-1** | **删掉 `System.exit(0)`** | `BigModelHandler.onFailure`（L165）、`PPTHandler.onFailure`（L162） | **最值钱的一条**。现状是「星火一次抖动/429/签名错 → 整个 chat 服务进程退出」。改为：分类错误码（可重试 429/超时 vs 不可重试 401/400）→ 指数退避重试 → 前端可读错误气泡。简历可写「修复第三方长连接异常导致 JVM 退出的致命缺陷」 |
| **A-2** | **上下文外置 Redis** | 新增 `ChatContextStore`，替换 `BIGMODEL_MAP` + `historyList` | 一举解决面经 Q24/Q31/Q30 三个问题：内存泄漏（只 put 不 remove）、重启失忆、多实例上下文分裂、并发串扰。key `ai:ctx:{userId}` → Redis List，`RPUSH` + `LTRIM` 保最近 N 轮，TTL 24h。简历可写「会话上下文外置 + 多副本可水平扩展」 |
| **A-3** | **密钥/端点配置化** | `Constant.java` → `@ConfigurationProperties(prefix="spark")` | 现在改密钥要重编译重建镜像。改完「密钥零入库、按环境切端点」——这条是安全基线，面试必问项 |
| **A-4** | **修上下文裁剪与清空** | `canAddHistory()`（硬编码 `remove(0..4)` 且调用方再删一遍 → 双重删除）/ `removeSession()`（`for+remove(i)` 只删一半 → 应为 `clear()`） | 面经 Q22/Q23 已写好根因，改造后这两题从「认错」变「已修」 |
| **A-5** | **全局单例 OkHttpClient** | `BigModelHandler.send()` L61 每次 `new OkHttpClient.Builder().build()` | OkHttp 每条 Client 自带连接池 + Dispatcher 线程池，高频新建→线程暴涨。参考 `ApiClient` 里那个带 `ConnectionPool(100,5,MINUTES)` 的写法（面经 Q34） |
| **A-6** | **真正打开 `@EnableAsync`** | `chat/config/AsyncConfig.java`（当前被注释掉） | 面经 Q28 说 `@Async` 形同虚设。补 `ThreadPoolTaskExecutor`（有界队列 + 明确拒绝策略 + 线程名前缀），别用默认 `SimpleAsyncTaskExecutor` |

> ⚠️ **A-1..A-6 全在 `java/chat`**，只需重建 chat 一个镜像。但若动到 `java/common`（例如抽公共鉴权工具），**必须重建全部 6 个后端镜像**（项目铁律）。

**A-7（顺手，成本极低）：抽公共鉴权工具**
`BigModelHandler.getAuthUrl` / `PPTHandler.getAuthUrl` / `MyUtil.getAuthUrl` 三份 90% 重复，以及各写一遍的 `JsonParse/Header/Payload/Choices/Text` 内部类。抽成 `SparkAuthUtils.buildSignedUrl(host, path, method, apiKey, apiSecret)` + 公共 DTO。面经 Q8 已经把这段写成「我知道这是坏味道」——改成「我重构掉了」更强。

### 第 2 档：做出数字（1～2 天，简历的「量化」来源）

| # | 改什么 | 简历句骨架（数字必须实测填） |
|---|---|---|
| **B-1** | **token 预算治理**：把「字符数 > 12000 删 5 条」换成 token 估算 + 滑动窗口 + **早期对话摘要压缩**（超限时把最早期轮次喂给模型压成一段 summary 放进 system） | 「以滑动窗口 + 早期对话摘要压缩替代按字符数硬裁剪，30 轮对话 prompt token 由 X 降至 Y（-Z%），单轮调用成本下降 A%」 |
| **B-2** | **可观测埋点**：记录 TTFT（首 token 延迟）、总耗时、prompt/completion tokens、错误码，落 MySQL `ai_call_log` 表；暴露 `/chat/ai/metrics` | 「为 LLM 调用建立可观测：首字延迟 P95 = X ms，成功率 Y%，按用户/按天输出 token 成本台账」 |
| **B-3** | **用户级限流 + 熔断降级**：Redis 令牌桶（如 1 req/2s）+ 连续失败快速失败 → 降级为错误气泡 | 「引入用户级限流与熔断，第三方抖动不再传导为站内 5xx，故障期降级为可读提示」 |
| **B-4** | **（可选）PPT 生成异步化**：现状 `getPPT` 同步阻塞 + `Thread.sleep(200)` 自旋 + 逐章节串行调星火，实测必超时（面经 Q43 已算出 40s+）→ 投递 RocketMQ，消费者调星火，**复用已有 WebSocket 推章节进度** | 「将多章节 AI 生成的同步阻塞调用重构为 MQ 异步任务 + WS 进度推送，接口响应由 40s+ 超时降至 <200ms 返回任务 ID」 |

### 第 3 档：差异化（2～4 天，这才是真正拉起档次的一条）

#### C-1 【最推荐】Function Calling：让 AI 能用自然语言查站内数据

**为什么是它：**
- 复用成本极低：`java/common/.../client/search/SearchClient.java` 已存在（Feign → search 服务，`${service.search.url:...}` 已参数化），ES 三索引已打通；
- 它把项目从「聊天 Demo」变成「**LLM 接入业务数据的 Agent**」——正对 AI 应用开发岗的核心要求；
- 补上 1.3 节的口径漏洞（技术栈写了 Function Calling，项目里却无落地）。

**做法：**
1. 定义 2～3 个工具：`search_video(keyword, limit)` → 走 `SearchClient`/ES；`get_video_detail(videoId)` → video 服务；`get_user_info(userId)` → user_center；
2. 星火请求体加工具声明，模型返回 `function_call` → 后端执行工具 → 结果回灌对话 → 模型生成最终回答；
3. 工具调用可多轮（模型可能连续调两次）；
4. ⚠️ **落地前必须核实官方文档**：星火 v3.5 的字段名（`parameter.chat.tools` 还是 `functions`）、工具结果回灌时的角色名（`function` / `tool`）、以及 `function_call` 的返回结构。别照搬 OpenAI 格式。

**简历句：**
> 基于 Function Calling 将站内 Elasticsearch 检索封装为模型可调用工具（视频检索 / 视频详情 / 用户信息），实现「帮我在站里找 Python 教程」类自然语言检索，工具选择准确率 X%（N 条测试集），端到端 P95 = Y ms。

**⚠️ 必须同步改面经 Q64。** 现在那题答的是「为什么没做 RAG？——因为场景不需要」。做了 C-1 后要改成：「我上的是 **tool calling 而非 RAG**——站内是结构化可精确查询的数据（按关键词/UP主/简介检索），让工具去调 ES 比灌进向量库更准、更新更实时；RAG 适合非结构化知识（我在作文批改项目里用 ChromaDB 做的是这一类）。**两者的边界是「数据能不能被结构化查询」**。」这个答法比原来强得多，因为体现了选型判断。

#### C-2 【强烈建议，安全性】WebSocket 握手 JWT 鉴权

现状：`handleTextMessage` 里 `json.get("userId")` **直接信任前端传来的身份**——改个 userId 就能以他人身份发消息、并读到别人的大模型上下文。面经 Q55 说这是「最严重的漏洞」。

做法：握手阶段（`?token=` 或 Cookie）校验 JWT，把 userId 绑到 `WebSocketSession.attributes`，后续所有身份**一律从会话取**；顺带把 `setAllowedOrigins("*")` 改白名单（Q56 的 CSWSH）。

价值：这条改动量小、但**是简历/面试里最能体现安全意识的一条**，而且项目里网关已有 JWT 双 Token 体系可复用——正好构成「我发现了鉴权覆盖不全并补齐」的完整叙事。

#### C-3 【可选】AI 分身 / 群聊助手
用 UP 主历史视频标题+简介做 few-shot，生成「AI 分身」代回复粉丝私信（半自动，人工确认后发出）。产品叙事好，但工程含量低于 C-1，时间紧可不做。

## 3. 推荐组合与实施顺序

```
第0档 拿密钥 + 配环境变量
  ↓
第1档 A-1 → A-2 → A-3 → A-4 → A-5 → A-6 → A-7      （拆地雷，半天~1天）
  ↓
第2档 B-1 → B-2                                       （做出数字）
  ↓
第3档 C-2（改动小，先做）→ C-1（Function Calling）     （拉开档次）
  ↓
有余力再补 B-3 / B-4 / C-3
```

**为什么这个顺序**：
- A-1 是 10 分钟的改动、却是整个模块最严重的问题——**投入产出比最高，先做**；
- A-2 是 B-1/B-2/B-3 的共同地基（上下文不落 Redis，一切治理都只能停留在单进程内）；
- B-1/B-2 产出**数字**，而数字是简历里唯一能证明「你真做过」的东西；
- C-2 改动小、价值高，放在 C-1 前面；
- C-1 是压轴，改动最大，且需要先有 A-2（多轮上下文）才顺。

## 4. 简历改写对照

**改前（现状）：**
> 5. AIGC 创作链路：打通讯飞星火 WebSocket API（HMAC-SHA256 鉴权），经事件监听 + 异步回调将大模型流式响应实时回推前端，支持文生文与文生图；自研按主题生成整套 PPT 文案能力，多轮会话按 12000 字符阈值滚动裁剪。

**改后（第 1+2 档完成后的样子）：**
> 5. **LLM 链路治理与可观测**：定位并修复第三方长连接异常触发 `System.exit` 导致服务进程退出的缺陷，改为错误码分类 + 指数退避重试 + 前端可读降级；将多轮上下文由 JVM 静态内存迁移至 Redis（TTL + 长度上限），消除内存泄漏与多副本上下文分裂；以 token 预算 + 滑动窗口 + 早期对话摘要压缩替代按字符数硬裁剪，30 轮对话 prompt token 降低 X%；埋点 TTFT / token / 失败率，首字延迟 P95 = Y ms。（顺带把会话并发串扰、OkHttp 连接池复用、`@Async` 线程池一并治理）

**再加上（第 3 档完成后的新增一条）：**
> 6. **LLM 工具调用（Function Calling）**：将站内 Elasticsearch 检索、视频详情、用户信息封装为模型可调用工具，实现「帮我在站里找 Python 教程」式自然语言检索，工具选择准确率 X%（N 条测试集）；对第三方调用做用户级限流与熔断，故障期降级为可读提示；补齐 WebSocket 握手 JWT 鉴权，替换原先由客户端传入 userId 的可伪造身份方案。

**写作要点（对齐你作文批改那 6 条的标准）：**
1. 每条 = **动词 + 技术手段 + 解决的痛点 + 量化结果**；
2. 数字必须真跑出来（**不许编**——面试官会让你现场解释怎么测的）；
3. 变化量比绝对值更可信（「由 X 降至 Y」比「Y ms」更硬）；
4. 保留一句「为什么」：例如「上下文外置而非前端托管，是因为前端托管会被篡改且请求体膨胀」。

## 5. 怎么证明改好了（延续上一轮的做法）

上一轮修 4 个前端布局 bug 时你已经建立了很好的证据链习惯（before/after 截图 + 多档视口实测 + 零 console error）。这次同样要留证：

| 改动 | 证据 |
|---|---|
| A-1 移除 System.exit | 断网/改错密钥复现：改前进程退出、改后仅单会话失败且前端收到错误气泡（日志 + 进程存活） |
| A-2 上下文外置 | 重启 chat 容器后接着上文提问，模型仍记得（录屏/日志）；`redis-cli keys 'ai:ctx:*'` 有 TTL |
| B-1 token 治理 | 同一条 30 轮对话，改前/改后请求体 token 数对比（星火响应里 `payload.usage.text.tokens` 是权威值） |
| B-2 可观测 | `/chat/ai/metrics` 输出 TTFT P50/P95、成功率、token 汇总 |
| C-1 Function Calling | 固定测试集（如 20 条「找 X 类视频」提问）统计工具选择准确率，附 3 条典型 case 的实际输出 |

**测试集一定要自己写、自己跑、自己算** —— 面试问「准确率怎么来的」时，能答出「我构造了 N 条 query，人工标注期望工具，统计命中率」就赢了。

## 7. 风险与注意事项

| 风险 | 说明 |
|---|---|
| **成本** | 星火 v3.5 对话按 token 计费、TTI 按张、AIPPT 按次。B-1/B-2 的压测会真实烧额度，控制轮数与并发 |
| **密钥泄露** | 绝不可写进 `Constant.java` 提交。本项目 git 历史里若曾提交过真实密钥，**必须去平台轮换**，删文件不管用（面经 Q11 的答案要能落到"我做了轮换"） |
| **重建范围** | 只改 `java/chat` → 重建 chat 镜像；改 `java/common` → **重建全部 6 个后端镜像**；改 `docker/config/chat/` → 只需 `docker compose restart chat`；改前端 → `docker compose build frontend`（且**前端源码只改 `vue/labilibili/`**，`vue/src/` 是失效副本） |
| **不要为了简历编数字** | 面试官会让你讲测量方法。宁可写「-32%（自测 30 轮对话样本）」也不要写没有来源的「-80%」 |
