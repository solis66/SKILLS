# 04 他者视角与外部评价

> **调研口径**：本文件只回答一个问题——"别人怎么看他、外部世界如何评价他，以及他如何对待外部评价"。
> 刘竞峰不是公众人物。本次用中文检索其姓名，命中的全是**同名不同人**（同花顺的证券从业者、深圳市南山区人民医院一位主治医师、一位个体经营者），没有任何一条指向他本人，也没有可引用的报道、访谈或社区评价（语料中他也从未提及自己有博客、公众号、技术专栏或粉丝量），因此本维度的证据几乎全部来自三类"准外部"材料：**招聘流程留下的痕迹**、**可被第三方点开的公开仓库**、**他转述的他人期待**。
>
> **来源标注**：`[一手:...]` = 本人原话/原稿；`[协作:...]` = AI 协作产出（可能被大幅改写，权重降低）；`[外部:...]` = 本次调研直接抓取的公开数据（GitHub API / 本地 git 元数据）；`[检索:...]` = 我在给定语料内做的全文检索（含"无命中"这类阴性结果）；`[推测]` = 我的推断，非证据。
>
> 全文 **50 条**要点、约 100 处来源标注：一手 56 处、AI 协作产出 23 处、本次直接抓取的公开数据 12 处、语料检索 3 处、明确写出的 `[推测]` 9 处。凡是"谁夸过他/谁拒过他"这类直接评语，本文件中**一条都没有**——这不是漏找，见第九节。

## 三、他自己写下的"面试官模型"

这一节的材料是 AI 协作产出（409KB 的面试手册），但它是**围绕真实代码逐行核对**生成的，且被他一再调用（IDE 里打开着这份文件 `[一手:user-turns.jsonl#L19]`），可以视为他对外部评判标准的理解。

- **他把面试失败的主因归给"讲不出所以然"，而不是"项目不够好"**："大多数候选人面试挂在同一个地方：简历上写了 22 个技术栈，面试官随便挑一个问'这个在你项目里干什么用的'，答不上来" `[协作:articles/interview-qa.md#L14]`。
- **他给问题分了四级风险，最高一级叫"送命"**：`[送命]` = 答错会被判定为"没真做过"，应对策略是"必须坦诚承认，然后补正确做法" `[协作:articles/interview-qa.md#L27]`。这套分级本身就是他对"面试官如何识伪"的建模。
- **手册里明确列出了"面试中千万不要说的三句话"**，例如不能说自己用 Nacos 做了服务注册发现，因为"依赖都没引入，服务根本没注册" `[协作:articles/interview-qa.md#L4383-L4387]`。
- **它给出了通用于全部技术栈的原则**："凡是简历/README 写了但代码里没有的，被问到时都要主动'降级表述 + 补上正确做法'" `[协作:articles/interview-qa.md#L4389]`。
- **手册对 22 项技术栈做了"真实度"核对，结论是 17 项真用、5 项有问题**（Nacos 依赖未引入、JAVE 压缩/去水印不存在、XXL-Job 任务定义不在仓库等）`[协作:articles/interview-qa.md#L4462-L4484]`。
- **他接收了这套"外部审稿"，并把它写成了面试策略**："面试官不会因为你项目有 bug 而淘汰你——他淘汰的是'不知道自己项目有 bug'的人" `[协作:articles/interview-qa.md#L4488]`；对应地，附录 B3 列出"必须能主动交代的 5 件事" `[协作:articles/interview-qa.md#L4438-L4442]`。
- **`[推测]`** 他对"被看穿"的焦虑明显高于对"技术不够强"的焦虑。整份手册的重心是"别被当场查出来"，而不是"把不会的补会"——这与第二节"零面试"的现实叠加，说明他准备的是一场还没到来的对话。
