# Imperial Dev Team · 三省六部软件开发团队

以中国古代三省六部制为组织蓝本的 AI 软件开发流水线 skill：把用户（皇帝）的一个想法变成**可运行的 MVP**。各部 AI 分工接力、互不越权，三处关键节点必须由皇帝亲自批准。

## 组织架构

| 角色 | 职责 | 产出 |
| --- | --- | --- |
| 皇帝（用户） | 三道门禁：批准 PRD / 批准开工 / 最终验收 | 批准记录 |
| 尚书省（总调度） | 只派活与路由，不做任何设计决策 | 看板状态、圣旨档 |
| 中书省 | 需求分析 + 竞品调研 | `00-prd.md` |
| 门下省 | PRD 审核 | 通过 / 驳回+缺陷清单 |
| 户部 | 架构选型 + API 契约 | `01-architecture.md` |
| 吏部 | UI 规范 + HTML 原型 | `02-ui-spec.md` + `mockups/` |
| 礼部 | 任务拆解为 DAG 看板 | `03-tasks.md` |
| 兵部 | 按层并行产码（前端/后端） | 源代码 |
| 刑部 | 计划预审 + 逐卡审查 + 评测 | `04-reviews/` + `04-evals.md` |
| 工部 | 部署、冒烟测试、交付 | `05-release.md` |

## 流水线（12 步）

```
需求 → 中书省出 PRD → 门下省审核 → 【皇帝①批准】
     → 户部架构 → 吏部 UI → 【皇帝②批准开工】
     → 礼部拆解 → 刑部预审
     → 兵部并行产码 ⇄ 刑部逐批审查（核心循环）
     → 工部部署冒烟 → 【皇帝③验收】
```

## 核心机制

- **三权分立**：尚书省只调度不决策；部与部之间只传 `docs/imperial/` 下的固定工件、不传对话；任何部不得修改非自己产出的工件，问题按回退路由表退回 owner 部。
- **循环上限**：所有驳回-修复循环（PRD 审核 / 计划预审 / 任务卡返工 / 部署冒烟）累计 2 轮，第 3 轮带分歧呈皇帝裁决，绝不无限循环。
- **断点续跑**：技能触发先扫描 `docs/imperial/` 现场证据推断进度，从断点继续，已完成工序不重跑；一切「是否已批准」只认圣旨档 `99-decrees.md`。

## 使用方法

1. 将 `imperial-dev-team/` 目录放入你的 agent 技能目录。
2. 在空仓库中对它说出需求，例如「从零做一个习惯打卡 App，要求完整文档和部署」，流水线自动启动。
3. 三处皇帝门禁会主动询问你：准奏 / 驳回+理由。

**适用边界**：仅支持绿地项目（空仓库从零搭建），交付物为 MVP 而非生产级产品；已运行项目中途加功能可从任一环节续跑，但不做存量代码改造。
