# 任务看板

> 本模板由 **礼部** 填写。文件位置：目标项目 `docs/imperial/03-tasks.md`。
> 填写规则：每张任务卡必须声明**文件范围**，同批并行派发的卡文件范围不得相交（共享文件入独占范围或拆前置串行卡）；看板首卡固定为「工程脚手架卡」、末端固定为「集成卡」；验收标准必须溯源到 `REQ-` / `UI-` ID；本部不做技术决策、不改 PRD 范围（发现问题上报主调度，不擅自处理）。

## 任务卡字段

| 字段 | 说明 |
|---|---|
| ID | `T-001` 起全局唯一 |
| 范围 | 做什么，一句话 |
| 文件范围 | 该卡独占的文件/目录（以架构决策书目录规范为边界），同批并行卡不得相交 |
| 负责角色 | 前端 / 后端 |
| 验收标准 | 溯源 `REQ-xxx` / `UI-xx`（照抄或细化其可判定描述） |
| 契约接口 | 实现或消费的 `API-xx` 端点 |
| 依赖 | 依赖的卡 ID（无依赖即可并行） |
| 状态 | 见下方状态机 |

## 状态机

状态枚举（全看板统一，断点续跑以此字段推断进度）：`pending / coding / reviewing / rejected / done`

| 状态 | 含义 | 谁改 |
|---|---|---|
| pending | 未开始 | 主调度派发时置 coding |
| coding | 兵部实现中 | 主调度派发时 |
| reviewing | 已交刑部审查 | 主调度收到完成报告时 |
| rejected | 刑部驳回（挂缺陷票 `D-xx`） | 主调度收到驳回时 |
| done | 刑部 pass | 主调度收到 pass 时 |

> 断点续跑：主调度每次触发先读本看板状态字段推断进度，从最早未完成工序续跑。
